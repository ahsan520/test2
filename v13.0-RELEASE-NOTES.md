# Alpha Terminal v13.0 Release Notes — Browser Table Fetch Fix

## What changed

This release targets the symptom you were seeing: the **PREDATOR APEX — Signal
Matrix** table loading field-by-field, slowly, with the console flooded by
CORS / 451 / 522 errors pointing at Binance and `api.allorigins.win`.

Only `js/api.js` changed. No other file was touched — `app.js`, `signals.js`,
`render.js`, and the headless `scripts/` jobs all call the exact same function
names with the exact same signatures, so this is a drop-in replacement.

### 1. TTL caching for slow-moving kline data (the main fix)

Previously, **every 15-second resync cycle** for every crypto symbol fired
4 separate Binance requests:

| Endpoint | Used for | How often it can actually change |
|---|---|---|
| `depth` (order book) | OB IMBAL | Every few seconds — genuinely live |
| `klines 15m` | CVD, MTF RSI | Every few minutes — genuinely live |
| `klines 4h` | 4H Bias | Once per 4-hour candle close |
| `klines 1d` | Daily Bias | Once per day |

The 4h and daily kline calls were being re-fetched every 15 seconds for data
that cannot have changed since the last fetch. `fetchCryptoExtra()` now caches
4h klines for 4 minutes and daily klines for 15 minutes, per pair. Depth and
15m klines are untouched — still fetched live, every call.

**Effect:** for a ~15-symbol watchlist, steady-state Binance/proxy calls drop
from ~60/cycle to ~30/cycle (and the 4h/daily calls that do still fire are
spread out, not synchronized to the 15s tick).

### 2. In-flight request coalescing

`batchCrypto()` is called once **per symbol** from `syncOne()`'s staggered
loop, but every call hits the identical `GET /ticker/24hr` endpoint (it
returns all symbols at once — the old code just wasn't taking advantage of
that). If 15 symbols are mid-sync within the same 100ms-staggered tick, that
was 15 real network requests for the same response.

`fetchBinance()` and the new `_fetchOneRaw()` helper now de-dupe by URL: the
first caller starts the request, every other caller in-flight for that exact
URL awaits the same promise. No code calling these functions needed to change.

### 3. Proxy chain hardened

- Added a 3rd fallback proxy (`api.codetabs.com`) so a corsproxy.io + allorigins
  outage doesn't leave the row with nothing.
- Switched `corsproxy.io` to its documented `?url=` query format (the old
  bare `?<url>` format still works per their docs, but `?url=` is what they
  recommend and is more consistent across their edge nodes).
- Each proxy gets **one retry** before falling through to the next — your
  console log showed `allorigins.win` failing with 500/522 (intermittent
  server errors), not consistent hard failures, so a quick retry on the same
  proxy often succeeds without needing to fall all the way through.
- Added a small global concurrency cap (4 at a time) on proxy requests, so a
  cold page load doesn't fire 15–20 proxy requests simultaneously and trip a
  provider's burst rate limit (codetabs.com in particular is 5 req/sec).

### 4. Kraken path (XMR) — removed one duplicate fetch

`fetchKrakenExtra()` (used only for `XMRUSDT`, the one Binance-delisted pair)
was fetching the same 15m OHLC series **twice** — once for MTF RSI, once for
CVD — at slightly different `count` values. One fetch now backs both. Daily
and 4h OHLC for this path also use the same TTL cache as the Binance path.

## What did NOT change

- **Leaderboard buy/sell alert logic** (`js/position-tracker.js`) — reviewed
  and left as-is. Config defaults (`minScore: 9`, `cooldownMins: 60`,
  `holdLockMins: 20`, `exitCvdCycles: 3`) match the README and the headless
  `leaderboard-decider.js` exactly. No update needed here.
- **Headless runner / GitHub Actions** (`scripts/*.js`, `.github/workflows/alerts.yml`)
  — already on the `process.cwd()` path fix and offset cron schedule from
  v10.2/v10.3. Not touched.
- **Table rendering / diffing** (`js/render.js` `patchSymbolRow()`) — already
  diffs against last-rendered value before touching the DOM. The slowness
  was upstream of rendering, not in it.

## Installation

Replace `js/api.js` with the new version. Optionally also update
`js/config.js` (`APP_VERSION` bump only — cosmetic, no functional change).

No watchlist, position, or alert-config migration needed — same localStorage
keys, same data shapes, same function signatures throughout.

## Verifying the fix after deploy

1. Open the page, open DevTools console, hard-refresh.
2. You should see far fewer `allorigins.win` entries — most calls should now
   resolve via `corsproxy.io` (check the Network tab; failed/blocked Binance
   direct calls are expected and harmless, the proxy fallback is the
   intended path for a GitHub Pages origin).
3. Watch the table for ~2 minutes: 4H Bias / Daily Bias columns should still
   update, just not on every single 15s tick — that's expected, they're now
   TTL-cached.
4. If you still see heavy proxy failures after this update, it likely means
   all three free proxy providers are rate-limiting from your visitor volume
   — at that point the next step would be a self-hosted lightweight proxy
   (e.g. a Cloudflare Worker) rather than further client-side tuning.
