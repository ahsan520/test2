# Alpha Terminal v10.2 Release Notes

## What's new

### 1. Path Resolution Fix (Critical)
- **Issue in v10.1**: `market-fetcher.js` was using `__dirname` which didn't resolve correctly in GitHub Actions runners, causing `market-data.json` to be written but not persisted to the repo.
- **Fix in v10.2**: Switched all path resolution to `process.cwd()`, which reliably works in the Actions environment.
- **Result**: `market-data.json` now commits properly and Job B can read the data.

### 2. Cron Schedule Optimization (Recommended)
- **v10.1**: Job B ran at `*/15` (0, 15, 30, 45), overlapping with Job A at `*/5`.
- **v10.2 recommended**: Change to explicit minutes `2,19,36,53` for Job B, ensuring Job A always runs 2+ minutes before Job B with zero overlaps.
- **Update your workflow**: Replace the Job B schedule line in `alert-runner.yml` from:
  ```yaml
  - cron: '*/15 * * * *'
  ```
  to:
  ```yaml
  - cron: '2,19,36,53 * * * *'
  ```

### 3. Comprehensive Audit Logging
All three job scripts now log detailed audit information to `scripts/audit.json`:

#### Job A (market-fetcher.js)
- `fetch_start`: When data fetch begins
- `fetch_complete`: Success count, failure count, per-symbol results
- `fatal_error`: If the job crashes

#### Job B (leaderboard-decider.js)
- `job_start`: Beginning of the decision cycle
- `position_opened`: Each buy signal that fires (pair, setup, score, entry price, score source)
- `buy_cycle_complete`: Summary of total symbols processed, signals found, positions opened
- `market_data_empty`: If Job A hasn't written data yet
- `fatal_error`: If the job crashes

#### Audit File Structure
`scripts/audit.json` is a rolling array of up to 500 entries. Each entry:
```json
{
  "timestamp": "2026-06-23T20:38:27.000Z",
  "job": "market-fetcher|leaderboard-decider",
  "action": "fetch_complete|position_opened|etc",
  "...details": "specific to the action"
}
```

## How to View Audit Logs

### Option 1: GitHub Repository (Recommended)
1. Go to your repo → **Code** tab
2. Navigate to `scripts/audit.json`
3. Click the file to view the full JSON array
4. Most recent entries are at the bottom

This is the easiest way to monitor what the headless runner is doing in real-time without needing any setup.

### Option 2: Dashboard GUI (Future Enhancement)
The dashboard already syncs `audit.json` from GitHub. To add an audit log viewer:
1. In your GUI, add a new panel/route that reads `audit.json` from GitHub API
2. Filter/sort by timestamp or job type
3. Display summary metrics (signals per hour, success rate, etc.)

For now, you can manually inspect the file on GitHub after each run.

## Installation & Migration from v10.1

1. **Replace these files in `scripts/`:**
   - `alert-runner.js`
   - `leaderboard-scanner.js`
   - `market-fetcher.js`
   - `leaderboard-decider.js`

2. **Replace `.github/workflows/alert-runner.yml`:**
   - Use the new `alert-runner-v10.2.yml` content
   - If you already customized the schedule per my suggestion, replace only the `run` and `git add` steps, keeping your custom cron schedules

3. **Create the initial audit file (optional but recommended):**
   ```bash
   echo "[]" > scripts/audit.json
   git add scripts/audit.json
   git commit -m "chore: init audit log"
   git push
   ```

4. **Trigger a manual test run:**
   - `workflow_dispatch` → `mode: fetch` (should populate `market-data.json`)
   - Check `audit.json` after 30 seconds — you should see a `fetch_complete` entry
   - `workflow_dispatch` → `mode: decide` → `dry_run: true`
   - Check `audit.json` — should show `position_opened` entries if any symbols scored ≥9

## Testing the Path Fix

If you were experiencing "No changes to commit" in v10.1:
1. Delete the old empty/broken `market-data.json` from your repo (if it exists)
2. Deploy v10.2
3. Run Job A manually via `workflow_dispatch` with `mode: fetch`
4. Check that `market-data.json` now appears in your repo within seconds of the run completing

## Known Limitations

- **Audit log size**: Limited to 500 recent entries per file. If you need long-term history, export `audit.json` periodically to an archive.
- **Dashboard integration**: Not included in v10.2 — add UI for viewing audit logs in your GUI whenever convenient.
- **Real-time alerts**: Audit logs commit after the job completes, so there's a 1-2 minute lag from when an event happens to when it's visible on GitHub.
